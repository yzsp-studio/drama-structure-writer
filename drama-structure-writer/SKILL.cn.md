# 结构式剧本创作

## 核心使命

本 Skill 用于创作与优化中文长剧 / 中剧 / 短剧剧本结构：

- 长剧：通常 24-40 集，单集 30-45 分钟。
- 中剧：通常 20-30 集，单集 5-15 分钟。
- 短剧：通常 30-100 集，单集 1-3 分钟。

用户提供的《中剧剧本结构通用模板》只能作为结构参考，不能把其中“30集中剧”“5-15分钟”等示例硬套到长剧或短剧。所有集数、幕式边界、关键锚点、单集节奏、爽点密度和伏笔回收都必须根据剧种、总集数和单集时长动态计算。

## 最高优先级交互规则：自动抉择与最小必要提问

本 Skill 对技术事实和可推导信息仍是“自动抉择型”，但所有叙事方式抉择必须优先弹窗。进入任务后必须先读取 `references/auto-decision-chain-qc.md`，建立 `decision_lock`，并在每个阶段执行 `chain_lock_qc`。

能从用户明说、文件名、标题、正文、已有上下文或可统计事实得出的信息，必须自动锁定并继续执行，不得反复弹窗。只有会改变剧情、人物关系、结局、总集数、剧种、单集目标时长、对白保留策略、输出拓扑或不可逆创作方向的未知项，才弹窗。

尤其需要锁定并记录来源：

1. 剧种：长剧 / 中剧 / 短剧；
2. 总集数；
3. 单集目标时长；
4. 平台与目标受众；
5. 题材、尺度与类型边界；
6. 当前任务是新创作、优化、诊断、扩写还是重写；
7. 是否逐字保留已有对白；
8. 输出完整剧本、分集大纲、结构表还是诊断报告；
9. 叙事方式：线性推进、倒叙开场、插叙补因、平行叙事、交叉剪辑、蒙太奇并置、多线群像、限制视角、不可靠叙述、章回单元、环形结构、伪纪录/采访式或混合方式。

如果用户明确说“随便 / 你定 / 按推荐 / 继续 / 你判断”，采用推荐方案并记录为 `user_authorized_default`；若是格式、统计、时长、推荐分镜数、QC、断句、重复句、平台尾巴删除等不改剧情事项，直接自动执行并记录 `auto_continue`。
## 最高优先级补丁：叙事方式弹窗选择

凡涉及新创作、扩写、整剧方案、分集大纲、单集剧本、结构优化或重写，并且需要决定“故事如何讲述”时，必须在结构设计前读取 `references/narrative-method-selection.md`。叙事方式不是普通可静默推断事实：必须用 `question` 弹窗，把推荐选项放第一位，说明为什么适合当前题材 / 集数 / 平台，并提供 4-6 个相关备选。

适用范围包括：线性推进、倒叙开场、插叙补因、平行叙事、交叉剪辑、蒙太奇并置、多线群像、限制视角、不可靠叙述、章回单元、环形结构、伪纪录 / 采访式或混合方式。只有用户已经明确指定叙事方式时才可跳过弹窗，并记录为 `user_explicit`。如果用户说“你定 / 按推荐 / 继续”，采用推荐项并记录为 `user_authorized_default`。

选定的 `narrative_method` 必须写入 `decision_lock`，同时记录推荐理由、信息释放规则，以及蒙太奇 / 插叙 / 交叉剪辑等使用边界，防止后续剧本静默改变叙事方式。


进入任何阶段前，必须按需读取 `references/` 下对应文件；不得只靠历史摘要继续。任何阶段不得跳过 `decision_lock` 与 `chain_lock_qc`。

## 快速路由

0. 所有任务先读取 `references/auto-decision-chain-qc.md`，建立自动抉择锁与全链路连环锁 QC；能自动判断的先自动锁定，只有 blocking unknown 才提问。但叙事方式选择必须按 `references/narrative-method-selection.md` 弹窗推荐后确认。
1. 只有灵感或题材：读取 `references/drama-type-specs.md` 与 `references/structure-formulas.md`，先确认剧种 / 集数 / 时长。
2. 要做整剧方案：读取 `references/structure-formulas.md`，输出幕式规划、关键锚点、集数段落、高潮与收束。
3. 要写单集剧本：读取 `references/episode-templates.md`，按剧种和时长套用单集结构变体。
4. 已有剧本要优化：读取 `references/optimization-diagnosis.md` 与 `references/qc-checklist.md`，先诊断再改写。
5. 从零完整创作：按顺序读取全部 references：剧种规格 → 结构公式 → 单集模板 → 优化诊断 → QC。

## 标准工作流

### 阶段 1：需求确认与锁定

自动确认、统计或收集：剧名、剧种、总集数、单集时长、题材、受众、平台、核心设定、任务类型、对白保留规则。能从用户、文件名、标题、正文、上下文或统计事实得出的值必须写入 `decision_lock`；只有 `blocking_unknown` 才弹窗询问。

### 阶段 2：剧种结构计算

使用动态公式，不使用固定 30 集示例。最终确定幕式 / 阶段设计前，必须按 `references/narrative-method-selection.md` 先弹窗确认叙事方式。每个项目都要计算：已选叙事方式与信息释放规则、幕式或阶段边界、第一集钩子、第一幕转折、中点危机或核心反转、后段大转折、高潮区间、大结局收束、钩子与回收密度。

### 阶段 3：人物与冲突系统

重要角色必须有：叙事功能、社会身份、核心能力、核心弱点、核心欲望、秘密或信息差、关系压力、成长弧光、剧情功能和独立时刻。反派必须有可理解动机、真实威胁、行动方法、弱点和退场 / 转化计划。

### 阶段 4：分集规划

每集或每个集群要写清：所在结构位置、开场钩子、主冲突、多线推进、情感转折、爽点或付费点、伏笔埋设 / 回收、结尾钩子、下集衔接。

### 阶段 5：剧本文本

默认中文输出，格式为：

```text
场次编号：
场景：
时间：
人物：
动作：
对白：
情绪 / 节奏：
结构功能：
```

用户已有对白默认不改，除非用户授权改写。

### 阶段 6：优化诊断

优化时不能直接重写。必须先给诊断：结构问题、钩子问题、节奏问题、人物动机问题、冲突升级问题、伏笔 / 道具追踪问题、对白问题、修复方案。修复会改变剧情、人物关系、集数、时长、结局、类型或基调时，必须弹窗确认。

### 阶段 7：质量检查

交付前读取 `references/qc-checklist.md`。如发现失败项，返回最近相关阶段修复。

## 默认输出物

按用户目标选择，不一次性堆无关内容：剧本结构卡、集数适配表、幕式 / 阶段规划、人物系统表、分集大纲、单集结构表、完整单集剧本、剧本诊断报告、修复方案、优化后剧本、QC 清单。

## 最高优先级补丁：仅格式规范化

当用户要求“统一格式规范优化剧本”或“只规范格式”时，必须读取 `references/format-normalization.md`。本模式优先于普通剧本优化：只规范格式，不做戏剧性改写，不增减原有剧情内容。

固定执行项：

- 分镜从数字 `1` 开始连续编号；
- 每组分镜固定标注 `（场次：时段 | 场景参考图 | 景别，机位 | 镜头运镜 | 自然微表情 | 自然体态 |）`；
- 人物台词前统一添加 `（人物情绪）（开口说道）`；
- 内心独白统一标注为 `（人物情绪）（内心独白os）`；
- 画外音统一标注为 `（人物情绪）（画外音vo）`；
- 若原文缺少字段且无法安全搬运，弹窗询问或标注 `待确认`，不得编造。

## 最高优先级补丁：台词数量、时长、分镜数量与长文完整性 QC

当任务涉及分镜、镜头组、单集脚本、视频任务、画外音、内心独白或口播段落时，必须读取 `references/dialogue-shot-duration-planning.md`。

执行顺序固定为：

1. 统计台词类型与中文字数；
2. 按语速、表演留白、道具读屏、动作复杂度和节奏系数计算 `duration_calculation`；
3. 根据计算时长和内容复杂度决定 `recommended_shot_count`；
4. 再进行分镜编号、固定字段头、台词 / OS / VO 前缀规范；
5. 长文必须执行 `segment_qc` 分段式 QC 与 `chain_qc` 连锁式 QC；
6. 只有 `full_document_qc.final_status: PASS` 时，才允许宣称全文完成。

不得为了压缩进固定分镜数或固定时长而删台词、加速朗读、牺牲表演留白或改动原剧情。后半部分不得写“同上 / 按前文 / 后续同理 / 略”。

## 最高优先级补丁：自动抉择与全链路连环锁 QC

任何创作、优化、诊断、规范化或长文处理任务，都必须读取 `references/auto-decision-chain-qc.md`。

固定执行顺序：

1. 建立 `decision_lock`：自动锁定可从用户、文件名、标题、正文、上下文、统计事实得出的信息。
2. 只对 `blocking_unknown` 弹窗；非阻塞未知项标注 `待确认` 或 `auto_inferred`，继续执行。
3. 每进入下一阶段，执行 `chain_lock_qc`，检查上一阶段锁、参考文件、产物、未解决项和能力项是否被继承。
4. 自动抉择不得跳过任何功能。若任务涉及结构、人物、分集、优化、格式、台词时长、分镜数量、长文 QC，对应 reference 与 QC 都必须执行。
5. 最终必须输出 `full_chain_lock_qc` 与 `completion_gate`。任一必需项未 PASS，不得宣称“全文完整完成”。
