# 叙事方式选择

本文件定义 `drama-structure-writer` 的叙事方式抉择规则。凡任务涉及新创作、扩写、整剧结构、分集大纲、单集剧本、结构优化或重写，且需要决定“故事如何讲述”，必须在进入结构设计或重写前用 `question` 弹窗让用户选择，并给出推荐理由。不得把叙事方式作为普通 `auto_inferred` 静默锁定。

## 最高优先级规则

1. 叙事方式属于高影响创作选择，会改变信息释放、场景顺序、悬念设计、人物理解路径和观众体验。
2. 即使可以从题材、平台或参考稿推断推荐方案，也必须弹窗呈现“推荐选项 + 备选项 + 合理化建议”。
3. 只有用户已经明确指定叙事方式（如“倒叙开场”“平行蒙太奇”“线性讲清楚”），才可直接锁定；仍需在交付里记录为 `user_explicit`。
4. 如果用户说“你定 / 按推荐 / 继续”，选择弹窗中标注为推荐的方案，记录为 `user_authorized_default`。
5. 既有剧本优化若只做诊断、不改写，可以先诊断；一旦修复方案涉及改变叙事方式或信息顺序，必须弹窗确认。

## 弹窗问题模板

Header: `叙事方式`

Question: `这版故事建议先锁定叙事方式。根据当前题材和目标，我推荐「{recommended_label}」，因为{reason}。你希望采用哪种讲述方式？`

Options must be concise and localized in the working language. Always put the recommended option first and add “（推荐）”. Offer 4-6 options maximum; do not overload the user.

## 常用叙事方式选项池

根据任务只选择最相关的 4-6 项：

1. `线性推进`  
   适合：短剧、中剧、强爽点、强因果、需要快速看懂的商业类型。  
   建议理由：观众理解成本最低，钩子—冲突—反转—回收最清晰。

2. `倒叙开场`  
   适合：悬疑、复仇、误会、命案、重大后果先行。  
   建议理由：先给结果或危机，再倒回原因，能增强开头吸引力。

3. `插叙补因`  
   适合：人物秘密、旧案、前史、亲情/爱情误会、身份反转。  
   建议理由：主线不被打断太多，但关键节点可补充动机与信息差。

4. `平行叙事`  
   适合：双主角、正反双方同步行动、家庭线与事业线并进、群像。  
   建议理由：可制造信息对照和时间压力，但需要清晰切线规则。

5. `交叉剪辑`  
   适合：救援、追逐、庭审、商业谈判、危机倒计时。  
   建议理由：通过两条或多条行动线交替推进，增强紧迫感。

6. `蒙太奇并置`  
   适合：成长变化、时间压缩、训练、创业过程、情绪累积、关系破裂。  
   建议理由：用片段并置压缩时间、强化情绪或主题，不适合承载复杂因果解释。

7. `多线群像`  
   适合：长剧、家族剧、职场剧、权谋、社区/医院/学校群像。  
   建议理由：能扩展人物网络和主题厚度，但必须控制主线优先级。

8. `限制视角`  
   适合：悬疑、惊悚、误会、主角认知逐步打开的故事。  
   建议理由：观众只知道主角知道的事，悬念更强。

9. `不可靠叙述`  
   适合：心理悬疑、记忆偏差、谎言、主观叙述。  
   建议理由：能制造反转，但需要最终解释公平、可回看。

10. `章回单元`  
    适合：长剧、探案单元、行业剧、成长型主角。  
    建议理由：每个单元有小闭环，同时服务整季大主线。

11. `环形结构`  
    适合：宿命感、因果闭环、开头结尾呼应、主题表达强的故事。  
    建议理由：结构感强，但不适合过度依赖爽点推进的短剧。

12. `伪纪录 / 采访式`  
    适合：真实事件感、社会议题、人物回忆、悬案复盘。  
    建议理由：能增强真实感和信息层次，但戏剧场面需要额外补足。

## 推荐逻辑

- 短剧 / 强爽点 / 1-3 分钟：默认推荐 `线性推进`，如有强后果钩子则推荐 `倒叙开场`。
- 中剧 / 5-15 分钟：默认推荐 `线性推进 + 插叙补因` 或 `平行叙事`。
- 长剧 / 群像 / 家族 / 职场：默认推荐 `多线群像` 或 `章回单元`。
- 悬疑 / 复仇 / 旧案：优先推荐 `倒叙开场`、`限制视角`、`插叙补因`。
- 训练 / 成长 / 创业 / 情绪累积：可推荐 `蒙太奇并置`，但要提醒它用于段落压缩，不替代主叙事因果。
- 救援 / 追逐 / 同时行动：推荐 `交叉剪辑`。

## decision_lock 字段

在 `decision_lock.locked_values` 中新增：

```yaml
narrative_method:
  value: 线性推进 | 倒叙开场 | 插叙补因 | 平行叙事 | 交叉剪辑 | 蒙太奇并置 | 多线群像 | 限制视角 | 不可靠叙述 | 章回单元 | 环形结构 | 伪纪录/采访式 | hybrid
  source: user_explicit | question_selected | user_authorized_default
  evidence:
  recommendation_reason:
```

不得使用 `auto_inferred` 作为叙事方式最终锁定来源。

## 输出要求

在结构卡、分集大纲、单集结构表或改写方案中明确写出：

- 已选叙事方式；
- 为什么适合当前题材 / 集数 / 平台；
- 信息释放规则；
- 是否允许插叙、蒙太奇或交叉剪辑；
- 哪些场景必须保持线性，避免观众看不懂。
